doc-comments skill — evaluation report

A controlled test of the skill's premise across two model tiers.

Headline. The skill's premise — that doc comments reduce agent discovery cost — is more specific than originally claimed. Human-written doc comments do reduce Sonnet's discovery cost meaningfully. The skill's generated doc comments do not — they make Sonnet do more work, not less. On Opus, doc comments of either kind add cost without changing behavior. The skill should not be used.

Full pre-registration of the Sonnet hypothesis (committed before Sonnet runs) is at preregistration-sonnet.md.

Opus's reading strategy is roughly constant — it reads the same number of files regardless of doc state. Sonnet's is doc-quality-dependent: trusted docs (human) reduce reading dramatically; untrusted/insufficient docs (skill-generated) appear to push the agent toward more reading, presumably because it doesn't trust the docs and verifies against the implementation anyway.

Methodology

Three checkouts of the same Swift codebase, identical except for doc-comment state:

  • Arm A — stripped: all /// and /** */ doc comments removed. 570 lines deleted across 52 files. Pure deletions.
  • Arm B — skill-generated: Arm A baseline + one full pass of the doc-comments skill. Added 681 doc lines across 54 files.
  • Arm C — human-written: pristine origin/main, doc comments written by the codebase author.

Each arm received the identical locked task prompt in fresh, non-interactive claude -p sessions (stream-json output, --permission-mode bypassPermissions, --disable-slash-commands, disallowed tools: Skill / AskUserQuestion / WebFetch / WebSearch, fresh process per run, working tree reset between runs). Sonnet runs were pre-registered: a hypothesis document was committed and pushed before any Sonnet run executed; it is preserved at preregistration-sonnet.md.

Task prompt (locked, same for all 45 runs across both models)

Add a method to WatchlistManager called markAllEpisodesOfSeasonWatched(mediaId:seasonNumber:episodes:context:) that marks every episode in a given season as watched. After marking, it should trigger the appropriate notification rescheduling so that any pending notifications for those episodes are cancelled or updated. Follow the existing conventions for ModelContext handling, episode persistence, and notification side effects.

Metric

Input tokens to first edit. Sum of input_tokens + cache_read_input_tokens + cache_creation_input_tokens across all assistant turns up to and including the first Edit / Write / MultiEdit / NotebookEdit tool call. This isolates the agent's discovery cost — work done before it knows enough to act. Secondary metrics: discovery tool calls before first edit, wall-clock duration, output tokens, total turns.

Honest caveats

  • N=10 per cell. 60 runs across both models. Real but small; treat effect sizes as directional with reasonable confidence intervals visible in the per-arm charts.
  • One fixture, one task, one language. Results characterize this combination. They do not generalize without additional fixtures, tasks, or languages.
  • Temporal separation. Opus runs occurred on 2026-05-14 (first 5 per arm) and 2026-05-15 (last 5 per arm); Sonnet runs all occurred on 2026-05-15. Anthropic infrastructure state may differ across days.
  • "First edit" is a proxy. It approximates the moment an agent has enough context to act. It does not capture quality of the resulting edit or downstream rework.
  • We measured a single skill pass on Arm B. A different stochastic pass of the skill might produce different docs and different results — though the skill's output is constrained enough by SKILL.md that we expect comparable behavior.
  • The Sonnet finding leans on the C arm. The strongest claim — "good docs help less-capable agents" — rests on Arm C. The B arm contradicts it for skill-generated docs specifically.
